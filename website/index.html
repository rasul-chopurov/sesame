What it does

Everything on the box, in one calm window.

Sesame reads your server the way you would — over SSH, read-only first — and turns what it finds into something you can act on.

Discover

See what is really running

One read-only probe finds sites in FrankenPHP/Caddy, Nginx and Apache, Laravel apps and their .env drivers, supervisor workers, databases, cron, certificates and the firewall — and tells you what needs attention.

  • FrankenPHP
  • Octane
  • Nginx
  • MySQL
  • PostgreSQL
  • Redis
  • cron
  • ufw
Isolated sites

A new site, sealed off

Each site gets its own Linux user, its own PHP-FPM pool or Octane, its own database user and Redis ACL. The web server can read public/ — never your .env.

  • own user
  • own pool
  • own DB
  • Redis ACL
Services

Databases in one click

Redis, PostgreSQL, MariaDB, MongoDB, Elasticsearch, S3 on RustFS and Reverb — bound to localhost, with generated passwords. Nothing is installed until you ask.

  • localhost only
  • keep data on uninstall
Deploys

Push to GitHub, deploy in Sesame

Link a site to a repository and branch. Sesame creates a read-only deploy key on the server, then fetches, installs, migrates and restarts workers.

  • deploy keys
  • migrations
  • workers
Cloudflare

DNS without the tab-switching

Domains, records, proxy on or off, cache purge — and a “point to this server” button for every site that isn’t pointed yet.

  • DNS records
  • proxy
  • cache purge
Safe by design

Every change is shown before it happens.

Sesame never changes a server behind your back. Plans are previewed, destructive steps ask you to type the name, and everything lands in an audit log.

Read-only first

Discovery never writes. It never reads passwords or keys from .env either.

Encrypted vault

Secrets are sealed with XChaCha20-Poly1305 under a key derived from your master password with Argon2id.

Confirm, then run

Each plan lists its steps. Drops back up first and need you to type the name.

Off the command line

Passwords travel over stdin and heredocs — never in argv, never in ps.

AI-friendly

Every action is a typed operation.

The app and the sesame CLI run the same plans, so scripts and AI agents can do what you do — with the same previews and the same audit log. MCP and REST are next.

# save a server and look around
$ sesame add prod root@203.0.113.10
$ sesame discover prod

# an isolated Laravel site with PostgreSQL
$ sesame do prod new-site shop.example.com --db postgres --yes

# Redis, bound to localhost, password generated
$ sesame do prod install redis --yes

Native & fast

Rust and GPUI. No Electron, no JVM — it opens instantly and stays light.

Nothing to install

Plain SSH. No agent, no daemon, no open ports on your server.

Three languages

English, Русский and Azərbaycanca, with light and dark glass themes.
